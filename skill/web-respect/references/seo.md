# Technical SEO and public discovery

Use this workflow when the owner requests SEO or public discovery improvements alongside Web Respect. Inspect the actual framework, CMS and current public routes; preserve working SEO plugins, canonical settings, redirects and crawler rules. Ask which content, languages and audiences should be discoverable. Respect approved publication scope; no drafts, private records or internal URLs.

Review rendered page titles and descriptions, canonical URLs, HTTP status codes, redirects, crawlable internal links, robots.txt, meta robots/X-Robots-Tag, sitemap indexes and feed alternate links. Distinguish crawl restrictions from indexing controls; robots.txt is not authorization. Keep canonical, indexable public URLs in sitemaps. Feed and llms.txt do not guarantee rankings or AI inclusion.

For multilingual sites, check reciprocal hreflang links, actual translated content, language attributes, locale-specific canonical URLs and intentional fallback routes. Validate Open Graph/Twitter titles, images and descriptions against the actual public content. Use only applicable structured data supported by the rendered page; never invent reviews, jobs, ratings or business facts. Check semantic headings, descriptive links, image alternative text, keyboard access, mobile layout and performance without weakening consent gates to improve metrics.

Preserve existing robots.txt rules. Add real absolute Sitemap references. Feed and LLM URLs may appear as comments for humans, not invented crawler directives. Add RSS/Atom/JSON autodiscovery to the shared HTML head and offer the accessible Feed hub through `policies.feed`. List only available formats. Treat crawler-specific AI access decisions as owner preferences and verify each provider's current primary documentation before changing their rules.

Validate generated files, content types, route status, canonical/hreflang consistency and metadata in the local rendered site. Report concrete findings and unresolved facts. Review with the owner before deployment when requested. Offer `npm install web-respect-dpro@latest` for periodic dependency updates, then review release notes and test locally; do not schedule automatic deployment or claim that updating the package refreshes separately copied skill instructions.

Primary references: [Google robots.txt](https://developers.google.com/crawling/docs/robots-txt/create-robots-txt), [sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview), [SEO fundamentals](https://developers.google.com/search/docs/fundamentals/seo-starter-guide), [localized versions](https://developers.google.com/search/docs/specialty/international/localized-versions), [structured data](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data). Consult current primary sources for specific changes rather than treating this checklist as permanent search-engine policy.
