# Audit output and completion

Keep the working report private unless sanitized publication is authorized. Reports must not include home paths, credentials, connection strings, real user records, cookie values, unredacted HARs or private infrastructure identifiers. Use repository-relative references and synthetic subjects.

Produce the following connected outputs, adapting detail to the system:

1. Scope and date: service/version/environments, review or implementation authorization, examined journeys/tools and access limitations.
2. Owner intake and applicability matrix: declarations versus verified facts; markets/states, entity/sector/children, applicable or provisional rules and current primary sources.
3. Service/data-flow inventory: purposes, data, recipients/subprocessors, account-specific locations, transfer evidence, retention and confidence.
4. Retention and rights map: datasets, cleanup/holds/backups, subject mapping, request channels, deadlines with legal source, downstream deletion and responsible owner.
5. Findings: identifier, impact/priority, applicable rule or WCAG criterion, exact evidence/reproduction, status, recommended or implemented change, test result and decision owner.
6. Market-specific action plan: required controls for actual markets, engineering defaults, legal/business decisions, missing access and remaining verification. Include an explicit coverage list of reviewed and unreviewed topics/jurisdictions.

Use statuses: verified technical behavior, confirmed defect, needs evidence, needs legal determination, not applicable with documented reason, fixed and retested. Avoid a single compliance score or all-laws pass. Confidence and severity are separate; lack of evidence is not proof of either failure or compliance.

Examples of sound conclusions:

- A configured EU database region is observed; support-access and backup countries remain unverified. Request redacted tenant configuration and processor evidence.
- Analytics fires before refusal in a clean session. Fix its actual initialization and server forwarding, then replay refusal/withdrawal tests.
- Consent receipt deletion works; account records and provider exports are not covered. Add subject-scoped workflow and synthetic propagation tests.
- A local-language site and declared single-market audience do not resolve establishment/actual customer facts. Keep applicability provisional.
- Automated accessibility checks pass on sampled routes; screen-reader evaluation and checkout remain untested.

After changes, report exact tests and unresolved items. For package/skill distribution verify complete relative links and resources, installation in a temporary target, no overwrites of existing skills, pack contents and private-data exclusion. Keep published version claims aligned with registry/release evidence. Distinguish a newly downloadable skill from an older npm package containing previous instructions.
